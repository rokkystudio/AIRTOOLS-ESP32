# Проверка плана патча whitelist в `ieee80211_raw_frame_sanity_check`

> **Примечание.** Отчёт снят по архиву из `libnet80211_unpacked` (50 объектов,
> 1.48 MB, база Ghidra `0x13198`). Текущая сборка линкует
> `framework-arduinoespressif32-libs` 5.3.0 (52 объекта) — актуальные адреса
> патча, установка и резервные копии описаны в [`../PATCH.md`](../PATCH.md).

Источник: `libnet80211_unpacked/objects/ieee80211_output.o`
(sha256 `83c0057a24523e0cc43c0058c2cec3e95cfeae81af8a53e7ccf27e02a98011c4`, совпадает с manifest.json).

Секция: `.text.ieee80211_raw_frame_sanity_check`, файловое смещение `0x31CC`, размер `0x212`.
Ghidra размещает её по базе `0x13198` — это подтверждается всеми тремя адресами из плана.

## 1. Адреса и байты

| Ghidra | Смещ. в секции | Смещ. в файле | Было (word) | Стало (word) | Инструкция |
|---|---|---|---|---|---|
| `0x13284` | `0x0EC` | `0x32B8` | `0x0F067793` | `0x0C067793` | `andi a5, a2, 0xc0` |
| `0x132C0` | `0x128` | `0x32F4` | `0x0D000693` | `0x0C000693` | `li a3, 0xc0` |
| `0x132C4` | `0x12C` | `0x32F8` | `0x02D78C63` | `0x02D60C63` | `beq a2, a3, .L1077` |

Проверено побайтно в объекте: все три слова на месте, little-endian.

## 2. Кодирование

Собрано ассемблером `riscv32-esp-elf-as` (`verify_insn.s`):

```
0c067793  and  a5,a2,192
0c000693  li   a3,192
02d60c63  beq  a2,a3,+0x38   -> 0x164 = .L1077
```

Все три инструкции 4-байтные, размер секции не меняется.

## 3. Релокации

В секции есть `R_RISCV_BRANCH .L1077` по смещению `0x12C` (это как раз третье слово).
Линкер при финальной линковке пересчитывает только immediate-биты ветки
(`S + A - P`), поле `rs1` не трогает, поэтому замена `a5 -> a2` безопасна.
По смещениям `0x0EC` и `0x128` релокаций нет. `R_RISCV_RELAX` на этих трёх
словах тоже нет, релаксация их не перепишет.

## 4. Итоговая семантика whitelist

Management (type = 0), `frame[0]` = subtype:

| subtype | было | стало |
|---|---|---|
| `0x00..0x30` | reject | reject |
| `0x40`, `0x50` | allow | allow |
| `0x60`, `0x70` | reject | reject |
| `0x80` Beacon | allow | allow |
| `0x90` ATIM | reject | **allow** |
| `0xA0` Disassoc | reject | **allow** |
| `0xB0` Auth | reject | **allow** |
| `0xC0` Deauth | reject | **allow** |
| `0xD0` Action | allow | allow |
| `0xE0`, `0xF0` | reject | reject |

Отказ — `.L1076` (`0x132C8`), лог `unsupport frame type: %x%x`, код `0x102`.

## 5. Ветка Data/QoS не ломается

`a5` после `0x0EC` используется ещё в `.L1075` (`0x14E`):

```
sll a4, a5, 0x18
sra a4, a4, 0x18
bgez a4, .L1077
```

Проверяется только бит 7 `a5`, а он равен биту 7 `frame[0]` и при маске `0xF0`,
и при маске `0xC0`. Значит для Data/QoS вердикт не меняется (subtype >= 8
по-прежнему reject). Третье использование `a5` (`0x12C`) после патча заменено на `a2`.

## 6. Что происходит ПОСЛЕ whitelist (`.L1077`, `0x164`)

Whitelist — не последний фильтр. Далее по коду:

1. длина кадра: `24 <= len <= 1500` (проверяется раньше, до типа);
2. бит Protected (`frame[1] & 0x40`) должен быть 0;
3. `memcmp(own_mac, frame+10, 6)` — сравнение с addr2 (SA);
   - если addr2 **не** равен MAC интерфейса — функция возвращает 0 (пропускает) сразу;
   - если равен — идут дальнейшие проверки;
4. `en_sys_seq` (4-й аргумент `esp_wifi_80211_tx`) должен быть **true**, иначе
   лог `en_sys_seq should be true to avoid side-effect to WiFi connection` и код `0x102`;
5. `frame[1] & 0x3C` (retry/power/frag/more-data) должен быть 0;
6. для Management — возврат 0 (разрешено); для Data — проверки ToDS/FromDS.

Практический вывод: даже с патчем вызов
`esp_wifi_80211_tx(..., false)` для кадра, у которого SA = собственный MAC
(deauth/disassoc), вернёт `0x102`. Нужен `en_sys_seq = true` и чистые флаги.

## 7. Проверка на копии

`ieee80211_output.patched.o` — копия с тремя патчами. Отличий от оригинала
ровно 4 байта (`0x32BB`, `0x32F7`, `0x32F9`, `0x32FA`), размер тот же (91724).
Дизассемблер подтверждает:

```
ec: 0c067793  and  a5,a2,192
...
128: 0c000693  li   a3,192
12c: 02d60c63  beq  a2,a3,164 <.L1077>
```

## 8. Ограничения

- Патч надо вносить в член архива `libnet80211.a` (или в его копию), иначе линкер
  возьмёт оригинальный объект.
- Расширение неизбежно разрешает `0x90` (ATIM) и `0xB0` (Auth): при трёх слотах
  сравнения и масках `0xC0`/`0xE0` иначе `0xA0`+`0xC0` не добавить.
- `0x102` = `ESP_ERR_INVALID_ARG`; `0x3004` = `ESP_ERR_WIFI_IF`.
